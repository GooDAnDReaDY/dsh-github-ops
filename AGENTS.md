# AGENTS.md — dsh-github-ops

Внутренние инструкции для агентов, работающих с этим репозиторием. **В npm-пакет и в
GitHub-зеркало этот файл не попадает** (он в запретном списке).

## Что это

DSH-плагин, дающий агенту операции с GitHub: релизы, теги, защищённый универсальный
доступ к API, чтение репозитория и файлов, issues, pull requests с обзором, CI-проверки,
запуски workflow, секреты/переменные/rulesets/защита веток и санитизированная публикация
GitHub-зеркала.

## Границы дизайна

- **Не дублировать чужие плагины ради совместимости** и не патчить их. Свой клиент, свои
  конвенции.
- **Чтение свободно, запись — только явно**: мутации требуют `confirm: true`; удаление
  репозитория, его перенос и удаление организации запрещены outright (одно подтверждение
  их безопасными не делает).
- **Токен — только в сервисе учётных данных DSH**; в настройках хранится имя. Токен не
  попадает в логи, сообщения об ошибках, README и тесты.
- **Никаких путей, адресов и имён машин** в коде и документации.
- **Английский — исходный язык**, китайский обязателен; русский интерфейс приходит из
  `dsh-russian-lang`. Русских строк в коде нет (это проверяется тестом).

## Как устроено

```
lib/index.js                хост: конфиг, токен, обёртка tool(), подключение регистраций
lib/github.js               клиент REST v3 + GraphQL v4, транспорт внедряется (fetchImpl)
lib/tools/*.js              чистая логика операций (тестируется без сети и без харнесса)
lib/tools/register-*.js     определения инструментов для агента
lib/client.js               браузерная половина: карточка настроек
test/*.test.mjs             тесты без сети и без харнесса
scripts/publish-github.sh   канонический путь публикации зеркала (см. ниже)
```

Правила, на которых легко обжечься:

- **Хуки выше всех возвратов** в компоненте карточки — иначе React error 310.
- **Слот `plugins.item` требует `id`, а не `key`**; `label` — **статичная строка**
  (обращение к локали в label роняет весь клиентский батч).
- **Карточка проверяет СТАТУС снимка настроек**, а не значение: при `unavailable` поля
  не должны выглядеть рабочими.
- **Динамический `<style>` обязан иметь** `data-dsh-plugin="dsh-github-ops"`.

## GitHub-зеркало: только санитизированное дерево продукта

Зеркало — продуктовый канал, а не копия истории. Публикуется только состав npm-пакета
(`package.json → files`) плюс `.gitignore`, `LICENSE`, README-трио, `CHANGELOG.md`,
`cordis.patch.yml`. Запрещено даже при наличии в манифесте: `docs/**`, `AGENTS.md`,
`index.md`, `.gitea/`, `.github/`, кеши, `node_modules/`.

Публикация — **только** через `scripts/publish-github.sh --check` / `--push <ref>` или
через инструменты `gh_mirror_check` / `gh_mirror_publish`. **Никогда не делать
`git push github main` напрямую**: так 19–20.09.2026 в публичные зеркала уехал весь
dev-репозиторий. Force-push запрещён: история зеркала не переписывается.

## Перед PR и релизом

1. `npm test` — зелёный, без сети и без харнесса.
2. `dsh-plugin-preflight` — без FAIL.
3. `npm pack --dry-run --json` — ни одного файла > 262144 Б и ни одного служебного пути.
4. Issue → ветка → PR → merge в Gitea; публикация в npm/GitHub — только по явному
   «публикуем» владельца, после приёмки на изолированном test server и на production.
